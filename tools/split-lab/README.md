# 切分调参台

独立本地实验工具，使用 Demo 相同的 Node.js 24 / TypeScript / FFmpeg，不新增 npm 依赖、不启动 Demo、不读写业务库、不调用模型。用于确定商品素材的切分粒度；参数尚未写回正式素材处理流程。

Windows 双击 [启动切分调参台.cmd](启动切分调参台.cmd)，或在仓库根目录运行：

```powershell
node tools/split-lab/server.ts
```

打开 http://127.0.0.1:4196 。使用 PATH 中的 FFmpeg / FFprobe，可通过 `FFMPEG_PATH` / `FFPROBE_PATH` 指定；端口可用 `SPLIT_LAB_PORT` 设置。

1. 点击“选择视频”，由浏览器直接打开系统文件窗口。选择一条视频后，文件会暂存到本机服务，再点击扫描；页面只显示文件名，无需输入路径。首次需要扫描画面并生成浏览器播放代理。
2. 调整镜头变化阈值与最短片段时长，实时查看切点、片段数和时长分布。
3. 点击片段在原片定位；点击播放切分片段，按当前起止时间从原视频实际编码预览。可保存预览片段、记录参数对照，或导出 JSON 切分清单。

## 两个参数

- **镜头变化阈值**：对应 FFmpeg `scdet.threshold`，0–100 的画面变化分数；降低通常增加切点。
- **最短片段时长**：旧客户端 `planShots` 的顺序过滤规则，过近的切点或过短的尾段被忽略；不是 FFmpeg 编码参数，也不保证动作语义完整。整条原片本来就短于该值时仍保留。

沿用旧客户端的检测与过滤方式：一次用 `scdet=threshold=0` 收集变化分数，随后由共享 TypeScript 函数按所选阈值筛选，再按时间顺序过滤过近切点。扫描使用原始分辨率，不用播放代理检测。

2026-10-29 用户确认当前切分基线：**变化分数阈值 15.2，最短片段时长 1.9 秒**。调参台默认加载这组值，并可通过“当前方案”恢复；Demo 商品未处理队列已沿用这组基线，见 [素材处理说明](../../docs/harness/MATERIAL_PROCESSING.md)。调参台滑条不会修改 Demo 库中设置；“原实现”的 12 / 0.2 秒仅作对照。

## 结果与边界

- 用户原文件保持不变。浏览器选择的文件只传给 `127.0.0.1` 本机服务，暂存副本放在系统临时目录 `ecommerce-split-lab/uploads/`；扫描、代理和按需片段放在 `ecommerce-split-lab/<会话ID>/`，不会自动进入素材库或覆盖历史片段。选择窗口由浏览器原生文件控件直接触发，不调用后台 PowerShell 弹窗。
- 调参只重算切点，不反复扫描或整片导出。预览输出为 H.264/AAC、最大 1280×720（保留比例），用来检查边界，不是最终交付画质；重复播放同一范围会复用缓存。
- 参数比较记录保存在当前浏览器，按视频文件名、大小及修改时间区分；关闭服务后需重新选择并扫描视频。需要跨浏览器保留设置和范围，请导出清单。临时文件可能被系统清理。
- 这仍是画面变化检测；没有语义判断、命名、文案匹配或固定时长强切。最短时长调大可能把真实镜头变化合进一段，需观看确认。

## 针对性验证

```powershell
node --test tools/split-lab/lab.test.ts
```

测试使用临时合成视频，检查两参数的切点差异、真实扫描／预览、缓存复用和原视频不变；不调用外部服务。
