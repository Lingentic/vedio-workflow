# 商品素材切分与命名

## 用户操作与设置

在“素材中心 → 产品素材”选择一个商品目录。素材类型统一按“全部／视频切片／原始视频／图片／声音”筛选，不再叠加已处理／未处理筛选。选择“原始视频”后，勾选或全选当前搜索范围内尚未完成的原视频并点击“切分并命名”；成功的子片段出现在“视频切片”，显示短名称，可展开画面描述并预览。全部商品目录不能跨商品发起批处理。

“切分与命名设置”默认折叠，只提供两个全局参数：

| 参数 | 当前确认默认值 | 范围 |
| --- | --- | --- |
| 变化分数阈值 | 15.2 | 0.1～100 |
| 最短片段时长 | 1.9 秒 | 0.1～10 秒 |

设置保存到当前数据根目录 SQLite 的 `settings/material-processing`，只影响尚未建立切分计划的原视频。重试沿用原计划；不把已保存切点按新参数重算。独立 [调参台](../../tools/split-lab/README.md) 继续用于试验，其滑条不会修改正式库的设置。

原视频可通过浏览器原生文件控件多选导入，文件仅上传到本机服务，再复制校验到托管目录；不使用后台 PowerShell 视频选择弹窗。上游可继续调用商品／导入 API 提交按商品 ID 归档的本地文件；商品获取沿用主线采集服务；采集视频导入为原始视频，图片直接入库且不进入切分队列。

## 本地与模型的分工

1. 原视频复制、哈希校验、真实视频流探测后入库，`kind=source, processed=false`；不自动切分或调用模型。
2. 用户发起处理后，FFmpeg 在原始分辨率检测变化，按最短时长顺序过滤过近切点，保存固定切点。每个子片段 ID、父源及时间范围先事务保存，再导出媒体；验证时长后提交正式文件路径。
3. 为原视频生成保持时间轴的分析代理，烧录 `SHOT_001` 等编号，一条原视频发起一次命名请求。代理静音，模型只描述实际可见画面，不把字幕／口播营销结论当成视觉事实，不改变切点。
4. 模型只返回每个固定 `shot_id` 的 `short_name`、`visual_description`。本地检查编号数量、归属、唯一性、字段和长度；全部通过后事务更新子片段 `title/description/processed=true` 与父源完成状态。

短名和描述保存在素材记录中，内部媒体路径保持资产目录下的固定文件名；关联以稳定素材 ID 为准。后续匹配可读取描述、时长和来源范围，本轮不接逐段语义选材或真实合成，不引入本地视觉模型／向量数据库。

## 命名服务配置

使用旧视频客户端同一条 Xinhankr Gemini 原生协议：`POST /v1beta/models/{model}:generateContent`，压缩 MP4 以 inlineData 传入。无新增 npm 生产依赖。

- 密钥／模型／地址优先取进程环境 `XINHANKR_API_KEY`、`XINHANKR_MODEL`、`XINHANKR_BASE_URL`。
- 配置文件可通过 `NAMING_CREDENTIALS_FILE` 或本机 profile 的 `namingCredentialsFile` 指定；默认读取旁边旧客户端切分引擎的 `.env`，不将其复制进仓库。
- profile 可覆盖 `namingModel`、`namingBaseUrl`。没有模型配置时沿用旧服务源码默认值 `gemini-3.6-flash`；实际界面显示加载到的模型，不把默认值当成账户可用性证明。
- UI 仅接收配置就绪布尔值与模型名，不能取得密钥。配置未就绪时仍可导入，但不可开始切分命名。
- 使用进程既有的 Node 网络配置；旧客户端专用的 `GEMINI_HTTPS_PROXY` 不由该模块设置。需要代理时按运行环境配置 Node 原生 HTTPS 代理后启动。

## 失败、恢复与文件保留

- 同批次按原视频串行处理，单条失败不阻断后面的原视频。服务端 busy 防止重复批次；用户切换页面不取消处理。
- 原视频正在处理时不能删除其子片段，避免导出／命名与删除同时更新同一条素材；其他素材仍遵守既有合成输入保护。
- 未命名的内部子片段 `processed=false`，不进入“视频切片”或可选素材；父源保留在“原始视频”，显示可复用片段数量和失败原因。失败不会删除已完成切片。
- 不自动重发任何命名请求。连接中断、返回结果或本地保存失败导致结果不确定时，保存 `naming.status=uncertain`；再次处理需前端站内确认和 API `confirmUncertain=true`。
- 请求回执及最终结果保存在该源的托管目录。重试优先复用完整命名结果；结果文件未落盘但有有效已返回回执时，本地恢复，不再请求。损坏回执／结果的本地读取错误不自动转成付费请求。
- 重启将未结束的 source.processing 标成 interrupted，已发请求标成 uncertain；不自动恢复网络任务。缺失子片段可以从托管原视频恢复，保持 ID、短名、描述和来源关系。
- 用户外部原文件始终保持不变。当前保留托管原视频用于来源与恢复；处理成功后仍在“原始视频”中显示“已切分”，可预览，但不能再次勾选处理；不清理该源。历史 `cleaned` 记录仍按原状态解释。

## 验证范围

`node --test demo/tests/material-processing.test.ts demo/tests/material-recovery.test.ts` 使用临时文件、真实 FFmpeg 和注入的离线响应，覆盖待处理入库、批次失败、编号校验、未命名不可选、重试保持 ID／文件、请求后磁盘保存失败恢复与缩略图阶段中断恢复。不会调用真实模型。

真实模型的中文命名质量和当前账户权益需要单独的明确授权验证；不能把本地配置就绪、模拟响应或可播放文件等同于语义准确。
