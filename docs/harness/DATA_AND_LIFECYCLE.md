# 数据与任务生命周期

字段定义以 [types.ts](../../demo/lib/types.ts) 为准，持久化入口为 [Store](../../demo/lib/store.ts)，状态转换由 [Workflow](../../demo/lib/workflow.ts) 执行。UI 标签与执行状态不能混用。

## 存储与身份

| 对象 | 标识／内容 | 变化规则 |
| --- | --- | --- |
| Product | `productId`；名称、价格、规格、卖点 | 库中编辑不自动写入已建立任务的 `productSnapshot`。 |
| Asset | `id`；kind、status、相对文件路径、媒体信息、productId 或固定 binding | 原始源与产出片段是不同记录；删除记录与文件清理可处于不同状态。 |
| 商品素材处理 | source 的 `processing/naming/splitSettings/cuts/outputs`；child 的 `parentId/sourceRange/title/description/processed` | 子片段 ID 与来源先事务保存；命名成功后才发布为已处理，失败不清理恢复材料。见 [切分与命名](MATERIAL_PROCESSING.md)。 |
| Task | `id`；商品／模板快照、文案、区间、方案、设置、预览、确认／完成状态 | 一个任务一条记录，覆盖当前进度，不自动保存多轮生成历史。 |
| Execution | `id`、`kind=copy/voice/render`、status、progress | 属于任务的一次执行；`done` 仅是该步骤成功。 |
| Interval | 稳定区间 ID、nodeIds、text、signature、音频、字句和节点时间 | 复用要求 ID／签名匹配、ready 且文件仍存在；confirmed 另决定是否已经完成音频确认。 |
| QueueEntry | `entryId` 与 `assetId` | 同一片段可在清单出现多次，不能用 assetId 当作唯一清单条目。 |

SQLite 位于 `数据记录/app.sqlite`，开启 WAL。当前仅有 `products`、`assets`、`tasks`、`settings` 四张表；完整对象存于 JSON `data` 列，部分标识和状态另存列供检索。没有把每句字幕独立建表，也没有 ORM。不能只凭开启 `foreign_keys` 就假设所有 JSON 引用都有外键约束。

```text
数据根目录/
├─ 数据记录/app.sqlite        及运行时 WAL / SHM
├─ 商品素材/<productId>/      托管来源和独立片段
├─ 固定素材/                 主播原片、通用画面、已入库 BGM
├─ 制作任务/<taskId>/
│  ├─ audio/                 当前任务 AI 配音
│  ├─ work/<runId>/          临时分段、字幕与拼接文件
│  └─ renders/<runId>/       基础画面与预览；最终路径以记录为准
└─ 缓存/                     可再生成的界面缓存
```

应用默认根目录取当前运行电脑的 Windows Videos 已知文件夹。`DEMO_DATA_ROOT` 可覆盖，`DEMO_PROFILE_DIR` 指定机器配置目录；不要在源码中写死用户名或在测试中复用用户的数据库。

## 三套正交状态

| 状态 | 取值 | 含义 |
| --- | --- | --- |
| `task.stage` | copy / voice / visual / preview | 当前制作工作区；进入下一阶段有确认和方案有效性前提。 |
| `task.execution.status` | running / done / failed / stopped / interrupted | 最近一次制作执行的状态，不代表最终完成。 |
| `task.completed` | false / true | 用户是否确认有效成片完成；true 后参数只读。导出不改变它。 |

- 创建：`stage=copy`、两个确认标志 false、completed false。
- 确认文案：固定当前节点；按区间 ID、文字／声音签名、音频是否仍存在决定复用或缺失；失效后续画面，进入配音。
- 新 UI 确认文案后自动配音：成功区间逐个保存；失败留在同一条记录，手动重试仅补未就绪区间。全部音频、节点时间和字幕有效后自动确认并进入 visual，不建立旧队列。文案不变且声音均可复用时直接进入，不重新付费调用。
- 旧 `voice/confirm` 接口仍会生成／重建方案，仅用于保留的后端流程，当前原型接入页不调用。
- 保存方案：进入 visual，更新方案；过期预览不能直接确认完成。手动时长不足可保存为 invalid，合成拒绝继续。
- 合成成功：进入 preview，保存输出路径、输入签名与轻时间线，仍为未完成。
- 确认完成：当前预览有效且实际 MP4 可探测，保存快照与时间信息，再 completed=true；后台排中间文件清理。

## 修改 → 失效范围

| 修改 | 保留 | 必须失效／重算 |
| --- | --- | --- |
| 待填文字或最终变量 | 其他仍匹配的区间音频、旧成功文件直到替代有效 | 文案／音频确认；变更区间声音；依赖的画面、预览和时间 |
| 某连续区间重配，文字不变 | 文案与其他有效声音 | 该区间时间、后续全片偏移、画面覆盖和字幕；声音时长可能改变 |
| 字幕／BGM／音量 | 文案、配音、有效商品序列及基础画面 | 当前预览及输出签名；进入成片页说明修改原因 |
| 明确重新填充画面 | 文案、配音及输出设置 | 商品序列与画面签名；不要借此重发模型请求 |
| 入选商品片段删除／不可用 | 文案、配音；已完成的独立成片 | 相关未完成任务的画面有效性与预览；不足时要求修复画面 |
| 库中商品资料修改 | 既有任务快照 | 新任务使用新资料；不静默重写旧任务 |

新视频生成页的素材选择只在页面内存中演示，刷新或换任务后不作为已保存进度；实际选材持久化待重构。旧方案记录保留但不自动转为新 UI 的逐段选择。HTTP PATCH 的文案草稿仍合并字段、串行发送，不能改回互相覆盖的并发保存。

## 运行、恢复与停止

- 当前一个服务只持有一个活动制作执行。前端切换模块不终止服务端工作；任务执行期间的编辑锁由前端与 Workflow 共同约束。
- Workflow 启动时把持久化 `running` 改为 `interrupted`，保留成功步骤并提示人工确认，不重新提交付费请求。不是云端结果查询／取消保证。
- 商品原视频的 processing 独立于制作任务；Library 启动只标记中断和命名不确定，不自动重新请求。托管原视频保留；历史 cleaned 源不自动回补。恢复与回执细节见 [素材处理](MATERIAL_PROCESSING.md#失败恢复与文件保留)。
- 停止接口只停止当前本地 render；不提供 copy／voice 主动取消。SIGINT／SIGTERM 对 render 有显式 abort 和等待；不能声称所有云请求都已优雅停止或退款。
- 故障、停止、恢复更新原 Task，不另建“恢复记录”。已完成但清理未 done 的任务可在重启后重新排清理。

## 删除与完成清理

- `deleted`：用户删除，保留墓碑；`unavailable`：暂不可用，不等于主动删除；`cleaned`：托管处理源已清理，不等于其成功子片段失效。
- 删除入口仅允许独立商品片段；活动 render 的 `inputIds` 保护实际输入。先保存 deleted，再尝试删除该资源托管文件与海报；失败记录 `cleanupError`。
- 完成清理先确认当前正式预览仍存在，再处理该任务 `audio/`、`work/` 和其他 render run 目录。当前实现保留正式预览所在的整个 render run 目录，因此同目录基础画面也可能保留；不能宣称物理上仅剩一个 MP4。文本／参数快照及轻时间线继续保留。
- 商品素材、固定素材、其他任务、外部原文件、导出副本都不是完成清理目标。路径归属校验不可省略。
- 清理失败记录 cleanup 状态和原因，不回退 completed。恢复草稿所必需的声音与文件不能在普通缓存整理中删除。
- 修改数据库或清理规则前，应读相应实现并用临时数据根目录验证；当前没有正式数据迁移框架或自动备份能力。
