# 电商视频混剪开源方案调研

调研整理日期：2026 年 10 月 15 日  
Markdown 转换日期：2026 年 10 月 16 日

后续需求已固定为阶段基线：[当前需求与待确认事项](当前需求与待确认事项.md)，更新于 2026 年 10 月 19 日。已确认文本驱动三色模板、可用公共资源的管理边界、模板与实例解耦、本机受管理媒体、资源逻辑删除及灰色失效引用处理，以及预览、正式完成、只读参数快照和临时配音清理规则。早期流程示例与该文件不一致时，以该文件为准；这里的开源调研不代表客户端已完成实现。

## 核心结论

现成开源项目已经覆盖配音、字幕、背景音乐、剪辑合成和部分任务管理，不必从零搭建整套视频生产系统。需要重点补齐的是电商专用的素材理解、内容结构规划和语义选片。

优先以 MoneyPrinterTurbo 作为成片执行底座的候选，参考 NarratoAI 和 FunClip 的素材分析与口播选段；研究 MoneyPrinterPlus 的段落模板交互，以及 OpenMontage 的阶段状态管理。可编辑时间线另行评估，不作为第一版批量成片的前置条件。

## 目标与范围

目标输入是一组已有商品实拍、真人口播、产品图片、商品事实及输出要求，目标输出是一条可审核、可修改的完整电商视频。当前重点是已有素材混剪，生成式 AI 仅作为补充镜头的可选能力。

| 路线 | 主要处理过程 | 采用位置 |
| --- | --- | --- |
| 已有素材混剪 | 理解与分段 → 规划和选片 → 音频字幕 → 合成 | 当前主线 |
| AI 广告生成 | 商品图片 → 创意分镜 → 生成镜头 → 合成 | 缺失镜头的补充 |
| 混合生产 | 实拍证明商品外观和功能，生成镜头补充创意 | 后续扩展 |

## 阅读方式

报告依次说明 AI 与 harness 分工、开源项目对比、重点项目和授权风险、第一版实现建议，以及后续验证事项。末尾保留来源链接，新增候选单独列出，便于继续调研。

证据等级分为已检查文档及部分代码、仅有候选线索、需要实际运行验证。检查代码不等于已完成本地部署、质量评测或生产稳定性验证。

## 工作流与职责分工

harness 指模型之外的运行环境，负责上下文、工具权限、方案校验、媒体执行、状态持久化和失败恢复。AI 负责判断与规划，harness 负责把决策落实为准确的剪辑操作。

| 阶段 | AI 或识别模型 | 程序与 harness |
| --- | --- | --- |
| 素材入库 | 画面描述、商品与动作识别 | 读取格式、时长、画幅、音轨；建立素材身份 |
| 切分与索引 | ASR 台词、语义段落、片段用途 | 镜头边界、时间段映射、分析缓存 |
| 内容规划 | 选择角度、段落结构和文案 | 提供商品事实，限制虚构卖点与优惠 |
| 候选选片 | 匹配文案与画面，对候选排序 | 先筛选商品和人物，再检查重复及可用时长 |
| 音频安排 | 选择风格，提出原声或旁白策略 | 保留口播完整性，生成或导入音频并获取真实时长 |
| 时间线生成 | 提出片段、字幕和剪辑决策 | 校验源片段范围，计算起点与持续时间 |
| 渲染合成 | 通常不需要大模型参与 | 裁切、画幅适配、字幕、混音与编码 |
| 审核与修订 | 检查音画语义和明显内容问题 | 检查黑帧、缺音轨、时长和字幕范围；局部重做 |

### 两种音频主线

配音驱动：确认文案 → 生成配音 → 获得真实语句时间点 → 匹配画面 → 字幕与 BGM。适合产品特写和使用场景，不应只按字数估算时间。

原口播驱动：选择完整句子 → 按语义组织顺序 → 用商品画面覆盖部分镜头 → 保持口播声音连续。人物出镜时不能让口型和新配音明显冲突。

人声、现场声、BGM 应分别配置。音量、淡入淡出、响度和压低 BGM 由程序执行。原素材已混入的背景音乐无法靠叠加新 BGM 消除。

## 优先复用的生产与分析能力

### MoneyPrinterTurbo

项目已有完整短视频流水线，支持本地图片和视频、批量生成以及 WebUI、API、CLI 等方式。任务代码中实际存在脚本、音频、字幕、素材和最终视频等阶段。适合先单独运行，以现有素材验证成片能力，再决定是否封装成客户端后端服务。

视频合成代码包含随机与顺序模式、短片段处理和源素材重复控制。其“匹配素材”不能直接理解为准确识别商品、逐句理解文案并自动挑选卖点镜头。需要在执行流水线之前增加电商专用规划与选片。

优先检查任务参数、配音与字幕时间轴、本地素材合成路径、取消和失败处理，以及重复渲染是否会重新请求付费服务。仓库采用 MIT 许可。

[仓库与使用说明](https://github.com/harry0703/MoneyPrinterTurbo)

[任务流水线代码](https://github.com/harry0703/MoneyPrinterTurbo/blob/main/app/services/task.py)

[视频合成代码](https://github.com/harry0703/MoneyPrinterTurbo/blob/main/app/services/video.py)

### NarratoAI

项目面向影视解说，支持视频理解、解说脚本、自动剪辑、配音、字幕及剪映草稿导出。值得参考的是画面分析如何转成带时间段的剪辑脚本，以及原声和旁白如何进入成片流程。

当前 README 把“根据口播、文案、视频素材自动匹配”列为未完成项。不能据此认定它已经解决大量商品实拍素材的自动选片，也不能只换一份提示词便假定能用于电商。仓库采用 MIT 许可。

[仓库与功能边界](https://github.com/linyqh/NarratoAI)

[剪辑任务代码](https://github.com/linyqh/NarratoAI/blob/main/app/services/task.py)

### FunClip

适合已有真人口播较多的场景。它以语音识别、时间戳和说话人信息为基础，支持按文字或说话人裁剪，并生成字幕。它是口播选段组件，不承担商品视觉理解或完整视频编排。仓库采用 MIT 许可。

[官方仓库](https://github.com/modelscope/FunClip)

## 模板与任务管理参考

### MoneyPrinterPlus

其混剪流程最接近“固定结构加可替换素材”：每个段落配置一个素材目录和一个候选文案文件，系统组合这些段落，添加配音、字幕、BGM 与转场，批量输出。服装场景可分为开场、版型、材质和结尾。

这能降低批量生产门槛，但段落关系及素材分组主要由用户事先建立，不能等同于把散乱素材交给 AI 自动编排。其页面代码可确认素材目录、文案路径、场景增减和批量生成入口。

授权风险：根目录 LICENSE 为 GPLv3，而 gui.py 与混剪页面文件头又声明未经作者许可禁止商用。应先获得明确授权，再决定是否集成代码；当前可研究其交互与流程设计。

[项目说明](https://github.com/ddean2009/MoneyPrinterPlus)

[混剪页面与文件头声明](https://github.com/ddean2009/MoneyPrinterPlus/blob/main/pages/02_mix_video.py)

### OpenMontage

值得参考的是 harness：用 YAML 定义阶段，用结构化产物表达场景、素材及剪辑决策，通过 checkpoint 保存状态，并校验产物及阶段前置条件。状态管理代码中确实存在 schema 校验、前置阶段检查和审批条件。

架构文档明确说明，外部 AI 编程助手就是调度者，没有一个独立的 Python 运行时调度器。若用于普通用户客户端，仍需要设计任务运行和模型调用边界，不能当作即插即用的成品 API。仓库采用 AGPLv3 许可。

## 建议的第一版实现

先验证一个成片底座，再补电商剪辑决策。避免同时接入多个完整应用，也不必先开发专业时间线编辑器。

### 最小生产链路

素材导入与索引 → 选择商品和视频结构 → AI 生成段落计划并选候选素材 → 校验并生成时间线 → 渲染预览 → 人工确认或局部修改 → 导出。

建议先提供使用场景、真人推荐、产品展示等有限结构。有合适口播时采用原声驱动，没有时采用配音驱动；素材不足时给出具体缺口，不自动虚构商品功效或未经确认的价格优惠。

| 成片位置 | 内容安排 | 音频处理 |
| --- | --- | --- |
| 0 至 3 秒 | 真人开场或明确的商品问题 | 保留完整原口播或使用旁白 |
| 3 至 7 秒 | 商品外观与关键细节 | 旁白介绍，原声按需保留 |
| 7 至 13 秒 | 使用过程和功能演示 | 配合语句长度，保留少量现场声 |
| 13 至 17 秒 | 结果或细节补充 | 用真实素材支撑表达 |
| 17 至 20 秒 | 收束与行动引导 | 完整句子结束，BGM 淡出 |

上述时间仅是结构示例。实际时长应依据真实口播、旁白、可用片段及用户设置计算，不应成为新的写死参数。

### 两份关键数据

素材记录至少包含 source_id、product_id、person_id、源片段起止时间、画面描述、台词、镜头用途、技术参数及质量信息。AI 返回的标签需要保留证据来源和人工修正入口。

剪辑决策至少包含素材 ID、源片段范围、成片位置、持续时间、画幅适配、原声策略、旁白、字幕和 BGM。源时间与成片时间必须分开，音视频分别描述。

### 任务恢复边界

按阶段保存状态、输入和输出；已完成的素材分析和配音尽量复用，改字幕或换片段不应整条重做。对付费调用保存请求和任务身份，区分仅重渲染、查询原任务和重新付费生成。

## 后续核实与验证

### 新增候选

[Abekyo Editor](https://github.com/abekyo/abekyo-editor)

优先核实 JSON 时间线的真实字段、校验接口、无界面渲染、MCP 支持，以及预览与导出的效果是否一致。

[OpenChatCut](https://github.com/jeongpiano/openchatcut)

核实多轨编辑、Agent 操作和渲染的实际完成度，区分可运行功能与规划项，再判断能否嵌入现有 Electron 客户端。

[NCA Toolkit](https://github.com/stephengpope/no-code-architects-toolkit)

核实裁切、拼接、字幕等真实接口与异步状态，并检查当前许可证及依赖。补充文本中的示意 API 路径不能直接当作正式调用指南。

[Semantic Clip Search](https://github.com/ADI4771/AI-Video-Editor-Semantic-Clip-Search)

核实文本检索到视频片段的实现，重点测试小商品、包装细节、相似商品和动作连续性。其结果可作为候选召回，不能直接替代商品身份确认与最终选片。

### n8n 与 ComfyUI

补充文本提供了商品参考图生成分镜、Gemini 与 Wan 多镜头广告、Veo 商品目录批处理和 JSON2Video 成片等方向。这些主要解决生成镜头与服务串联，不替代已有素材的理解和语义选片。相关模板链接需要补齐后再验证。

### 最小验证任务

准备同一商品的一组实拍素材、口播、已确认卖点和一段可授权 BGM。在独立实验中生成一条视频，保存素材索引、段落计划、剪辑决策和最终视频，不改客户端、不接自动发布。

检查商品是否正确、文案是否有证据画面、口播是否被截断、字幕与声音是否同步、画幅是否裁坏主体、背景音乐是否盖过人声。再只替换一个片段或一句文案，确认可以局部重做而不重复分析与付费。

在实际运行验证前，不对工期、成本节省比例或生产稳定性作承诺。
