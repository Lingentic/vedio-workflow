# 电商视频混剪当前需求与待确认事项

更新日期：2026 年 10 月 19 日。

本文件作为现阶段需求基线，记录已确认的业务约束，优先于早期调研报告中的示例和实现建议。后续有调整时再修改本文件，不把旧建议继续当成待选方案。当前处于需求与方案讨论阶段，不代表客户端已实现这些功能。

## 当前目标

用户通过文本制作和使用模板，将已有主播片段、必要 AI 口播和 AI 补全文案组织起来；需要时再配合用户上传的产品素材生成电商视频。

模板制作和使用独立于视频工作流。一次操作可以只制作并保存模板，也可以停在文案或配音准备阶段，不强制继续生成视频。

## 已确认的约束

### 文本驱动的三色模板

| 类型 | 内容含义 | 交互与资源关系 |
| --- | --- | --- |
| 红色 | 提前保存、完全可用的主播原话和原视频片段 | 界面展示文本，点击句子查看已绑定的视频资源 |
| 蓝色 | 提前在资源库准备好的必要 AI 口播及配音 | 界面通过文本操作，点击句子查看对应音频；可跨模板、跨实例复用 |
| 黑色 | 模板中待补全的文案位置 | AI 根据整体上下文生成文本，用户确认后再配音 |

- 用户主要在文本界面组装、排序和操作模板，不要求在时间线或视频缩略图上完成模板制作。
- 红色内容对应主播真实原话，不由 AI 改写；蓝色内容保留其必要口播属性；黑色是允许 AI 补全的部分。
- 黑色位置首先是内容待补位置，不预设为已经确定秒数的视频空白。
- AI 补全需要考虑整个模板的红色、蓝色内容及其他黑色位置，避免逐个孤立补写造成重复和断层。
- 素材准备、文案生成、配音和视频合成是可分开的阶段，不因完成前一步就自动执行后续生成。

### 两类片段及其音画关系

- 主播片段使用原视频对应的画面和原声，作为完整音画单元处理，不默认替换其声音。
- AI 配音片段使用 AI 文案与配音，画面使用用户上传的产品素材。
- 最终声音由主播原声与 AI 配音穿插组成，不是一条 AI 旁白覆盖所有画面。
- BGM 是独立音轨，不参与主播与 AI 配音的内容顺序决定。

### 主播素材跨商品复用

- 第一版只接收用户已经准备好的主播片段，不要求从长直播中自动筛选、切分或按句导出。
- 主播片段通常是通用话术，不出现具体商品，不应为每个商品重复保存一份。
- 以主播身份组织可复用素材池；某次任务引用其中的具体源片段。
- 产品素材与商品关联，和主播素材分开管理。产品维度可以限制某次任务允许使用的素材，不意味着主播素材归商品所有。
- 同一主播的多个片段需要考虑语义完整性、前后衔接、重复，以及画面和声音连续性。通用不等于任意位置都可使用。

### 业务归属与资源身份

| 对象 | 关联内容 |
| --- | --- |
| 商品 ID | 商品价格、卖点、商品视频片段等产品素材 |
| 主播 ID | 该主播已经准备好的直播视频片段，即红色资源 |
| 通用口播资源 | 蓝色文案与配音，不强制绑定具体商品 ID 或主播 ID |
| 模板 | 文本结构、红蓝资源引用和黑色待填位置，不强制归属于具体商品或主播 |

- 不强制绑定商品或主播，不等于没有资源自身的 ID。资源、模板和实例均需独立身份。
- 界面可以按商品、主播、资源类型组织；界面分类不要求与磁盘目录一一对应。
- 主播视频片段使用主播说的台词作为标题；商品视频片段使用对片段内容的描述作为标题。标题是展示信息，修改它不改变实际视频或原声。

### 公共资源的准备、修改与可用性

- 所有公共资源的导入、创建和修改都在资源库中完成。模板制作和实例界面不提供这些操作入口。
- 蓝色资源只有同时具备文案和与之匹配的有效配音，才能成为正式、完全可用的资源。
- 红色资源也必须具备对应台词和可正常使用的原视频、原声，才能进入后续制作阶段。
- 准备中、配音失败或文件缺失等不完整内容，不作为正式可选资源出现在模板制作、视频制作和实例创建的资源选择面板中。
- 资源库内的准备过程，不意味着用户已获得一条可被后续流程引用的正式资源。准备过程的具体界面和内部状态字段尚未锁定。
- 只修改资源名称，可以保留原 ID。
- 主播片段只修改台词标题，或者商品视频片段只修改描述标题，不创建新资源 ID，也不因改标题重新复制视频。
- 蓝色资源的配音文案不是单纯的展示标题。修改文案或配音中的任意一个，都按新公共资源保存：分配新 ID，提示用户取新名字，旧资源保持不变。文案改变后需重新生成匹配的配音；只更换配音时，文案可以沿用，但不能把旧音频当成新配音。
- 其他实际媒体内容变化，例如用另一段视频替换主播片段或商品片段的原视频，也不能覆盖旧公共资源，应保存为新资源、新 ID。
- 已引用旧资源的模板和未完成实例不自动切换到新资源。需要使用新资源时，在模板制作阶段显式选择。
- 文案和音频不匹配时不能把旧音频当成有效配音；修改后的新资源需重新完成准备，才能被后续流程选择。
- 新选择面板只显示完全可用资源；既有引用后来失效时，保留灰色占位并按下文的删除规则处理，不静默隐藏或替换。

### 哪些操作产生新的业务 ID

以下区分商品、主播、资源、模板和实例各自的业务 ID，不把临时文件名、模型请求号或后台防止旧结果覆盖的标识当成新的公共资源身份。

| 操作 | 新 ID 的归属 |
| --- | --- |
| 新建一条商品记录 | 新商品 ID |
| 新建一条主播记录 | 新主播 ID |
| 导入并保存一条新的主播视频片段 | 新资源 ID；关联已有主播不代表新建主播 |
| 导入并保存一条新的商品视频片段 | 新资源 ID；给已有商品添加素材不代表新建商品 |
| 创建一条新的、文案与配音齐全的蓝色资源 | 新资源 ID；准备阶段何时分配内部标识属于实现细节 |
| 修改正式蓝色资源的文案或配音，并保存新内容 | 新资源 ID；保留旧资源及其已有引用 |
| 更换主播或商品片段的实际视频内容，并保存新内容 | 新资源 ID；不是对旧视频原地覆盖 |
| 新建一个模板 | 新模板 ID |
| 新建一个使用实例 | 新实例 ID |

以下情况不因为操作本身创建新的公共资源 ID：

- 修改主播片段的台词标题、商品片段的描述标题，或资源仅用于管理的名称，不改变实际媒体内容。
- 将已有资源引用到另一个模板或实例中：使用原资源 ID；新建的模板或实例有自己的 ID，两者不要混淆。
- 编辑和保存现有模板：更新该模板的框架，不因此新建其引用的公共资源；只有显式新建另一模板才产生另一模板 ID。
- 在同一未完成实例中重写黑色内容、重新生成黑色配音、调整预览或覆盖成片：沿用当前实例，不把黑色工作文件自动变成公共资源。
- 删除资源：保留原资源 ID 并标记已删除；移除灰色失效条目只解除当前引用，不创建新资源。

### 红色资源在模板制作阶段确定

- 制作模板时可以通过选择资源、搜索原话等方式确定红色句子；具体辅助搜索和自动选取的实现尚未定案。
- 模板使用时，红色节点已经关联明确的视频片段，不再临时去主播池寻找内容。
- 点击红色句子是查看其对应资源，不是隐式重新选片。
- 同样的文本可能对应不同视频版本，不能仅凭台词文本识别具体资源。
- 自动选取或检索能力主要服务于素材准备和模板制作，不再被设定为每次生成视频的必经步骤。

### 蓝色配音独立生成与复用

- 蓝色部分可能在多个模板或多次使用中复用，应作为可单独操作的文本和音频资源。
- 不默认将相邻蓝色和黑色合成一个不可拆分的配音文件。此前整段合成的效率建议不作为当前方案。
- 蓝色文字和配音先在资源库准备齐全，再作为一个正式资源供模板引用。
- 模板和实例点击蓝色文本时播放已经绑定的配音，不在这些界面临时生成或修改蓝色资源。
- 不引入同一资源 ID 下多份可切换内容的隐式更新机制；实际内容变更按新资源、新 ID 处理。

### 黑色先确认文字再配音

- 使用模板时，AI 根据商品信息、红色主播原话、蓝色必要口播和模板规则补全黑色文本。
- 用户检查、修改并确认文本之后，再生成黑色部分的配音。
- 文案模板或类似 skill 的规则可以指导补全，不让 AI 随意改写已绑定的红色原话或必要的蓝色内容。
- 价格、活动、商品属性等内容应依据确认的信息；已有主播片段中的活动话术也需要与本次条件相符。
- 黑色生成内容属于本次使用的结果，不默认覆盖原模板的待补位置。
- 实例中允许反复生成、修改和确认黑色文本，以及重新生成黑色配音；不因此获得修改红蓝公共资源的权限。
- 黑色文本修改后，对应旧配音不再有效，需要重新生成；不因用户输入文字就自动提交付费配音请求。
- 黑色独立配音属于实例工作文件，不作为公共资源自动入库。
- 未完成和预览阶段保留继续制作需要的黑色配音。正式完成且最终视频已可靠保存后，可以清理这些独立音频，最终快照仍保留黑色台词和使用的生成参数。

### 资源 模板 使用实例三层关系

- 资源层保存可复用的主播片段、蓝色文本与配音、产品素材等内容。
- 模板层保存文本结构、节点顺序、红蓝资源引用，以及黑色补全位置和相关规则。
- 使用实例保存某次制作的输入、节点内容、实际资源引用、确认结果、工作进度及可选的视频结果。
- 模板提供参考框架，不是贯穿实例全生命周期的运行依赖。在实例初始化、为 AI 生成黑色部分提供上下文后，实例按自身已经保存的内容继续制作。
- 实例可以记录来源模板的 ID 和名称，用于说明“使用过哪个模板”；这些信息本身不建立持续的依赖或同步关系。
- 模板后续修改或删除，不改变已创建实例的内容，也不妨碍实例按已保存内容继续运行。
- 实例仍可直接依赖红蓝资源和产品素材。模板不再参与，不代表这些实际媒体依赖也随之消失。
- 模板制作只选择和组装公共资源，不修改资源内容；实例按自己的既定框架处理黑色部分和后续制作，不编辑红蓝资源或任意调整模板结构。
- 已删除资源的灰色引用可以移除。这是处理失效引用的例外，不是编辑公共资源或任意更改框架的入口。

### 实例保存、覆盖与恢复

- 实例是可以保存和续做的一次工作，不仅指完成后的视频记录。用户可以暂停实例 A，处理实例 B，再返回 A 继续。
- 保存当前商品输入、采用的节点与规则、资源引用、黑色文本、确认状态、已完成配音、制作配置、工作文件和当前阶段。
- 同一实例重新生成时覆盖当前结果，不保留多次生成历史或多套运行版本；用户显式新建实例时才另存一份独立工作。
- 暂停、失败或关闭客户端后，不应因清理工作文件而丢失继续制作的条件。保存工作进度不等于保证外部付费请求可以字面意义上的暂停和续传。
- 覆盖采用先完成有效的新结果、再替换当前结果的方式，避免失败后只剩损坏或缺失的输出。
- 旧请求晚返回时，不能覆盖已经被用户修改或重新生成的较新内容。这是防止结果错配，不是保留多次历史。
- 实例里的商品输入和生成内容需要保持对应，不在恢复时从公共库悄悄混入新价格、新台词或新音频。

### 预览、正式完成与参数快照

- 生成了可预览视频，不等于实例已经正式完成。
- 预览阶段允许调整 BGM、开关字幕；这些修改仍属于未完成的制作过程。
- 正式完成且最终视频可靠保存后，实例进入“已完成”状态，不再提供参数修改或重新生成入口；需要另做时新建实例。
- 已完成实例以独立成片和只读参数说明面板呈现。快照记录当时实际使用的商品信息、模板来源、红蓝资源信息、黑色台词、声音设置、BGM、字幕等相关配置。
- 商品之后涨价、公共资源之后修改、删除或模板之后删除，都不反向修改该快照和成片。
- 只读快照中的来源信息不是必须持续有效的运行引用；不承诺删除源资源后还能播放源片段或基于它直接重做。
- 已完成实例不因历史来源删除而变为不可用，也不在参数面板里提供“移除引用”这类编辑入口。

### 第一版本机存储范围

- 第一版只考虑用户本机存储，不要求登录、跨电脑同步或多人共享。
- 多人共享如有需要另行设计，不作为当前实现的前置条件。
- 程序安装目录与用户数据目录分开。为数据指定一个统一根目录，保存公共媒体、业务记录、模板、实例工作文件、成片和必要缓存；具体路径尚未选定。
- 导入媒体时复制到客户端管理的文件库，原文件保持不动，后续制作不依赖用户桌面或下载目录中的原始位置。
- 每个资源独立保存自己的托管媒体文件，不同资源不共享同一份物理媒体文件；第一版不做跨资源文件去重。
- 模板和实例引用已经入库的同一资源时，不各自重复复制一份长期公共媒体。
- 多个模板或实例引用同一个资源，只是同一资源的多处引用，不是多个资源共享一份媒体文件。
- 主播和商品视频只改标题时，继续使用原资源和原视频；蓝色资源修改文案或配音后，准备新的有效配音并另存资源和独立媒体文件。
- 第一版不做备份、恢复或云同步功能，也不把这些作为当前实现前置条件。
- 数据库方案、具体目录布局及缓存实现仍待技术设计；不预设每个实例保留多次运行目录。

### 公共资源删除与失效引用

- 删除资源前展示它被哪些模板和未完成实例引用，但不因为存在引用就强制禁止用户删除。
- 确认删除后保留原资源记录，包括原 ID、标题和“已删除”状态，供历史来源和灰色失效条目显示；不把该 ID 分配给新资源，不自动替换成另一资源，也不连带删除引用它的模板或实例。
- 删除资源时一起清理该资源独立拥有的托管媒体文件及对应缓存，不因模板或未完成实例仍有引用而继续保留这些媒体文件。
- 清理范围不包括用户最初导入的原文件、其他资源的文件或独立成片；清理媒体不等于删除已删除记录。
- 新资源选择面板不再显示该资源。已经引用它的模板和未完成实例保留灰色失效条目，并提供删除该条目的按钮。
- 灰色条目上的删除只移除当前模板或实例中的这一处引用，不再次全局删除资源，也不影响其他使用方。
- 不能用带失效引用的模板启动新的制作；未完成实例有失效依赖时，不允许进入下一步。
- 移除灰色条目后要重新检查本步所需内容是否齐备，不能把“引用已经移除”当成“必需素材已经满足”。因移除而改变的上下文和既有生成结果如何复核，见待确认事项。
- 已完成实例按只读快照规则处理，不要求用户为历史来源删除修复成片。
- 若媒体文件正被运行中的任务读取，先将资源标记为“已删除”，阻止后续使用，待任务结束或停止、释放文件占用后再清理；没有运行占用时随删除操作直接清理。占用解除前的暂缓清理不代表保留可恢复资源，也不影响其他界面显示已删除状态。

### 商品、主播与模板的删除边界

| 操作 | 当前规则 |
| --- | --- |
| 删除商品 | 未确定；是否提供该操作、删除范围及与未完成实例的关系，后续单独确定 |
| 删除主播 | 第一版暂不提供该操作，避免牵连红色资源与模板引用 |
| 删除模板 | 仅释放该模板对资源的引用，不删除公共资源，也不删除或修改已创建实例 |

- 商品删除整体先标记为未确定，不在本轮锁定删除商品时是否连带处理其素材、是否阻断未完成实例或采用什么具体交互。
- 已完成成片和参数快照作为独立单元、不随公共信息变化的原则保留，但不据此推定商品删除的具体规则。
- 删除模板只减少该模板实际持有的引用，不代替实例释放其独立的资源引用；来源模板信息不构成保留模板的理由。

### 视频时长需要业务确认

- 开发人员不能自行决定最终视频时长规则。
- 固定时长、时长范围或随内容自然形成，都只是待讨论选项。
- 主播片段和真实 AI 配音时长是编排计算依据，但不自动构成最终业务时长策略。
- 不把此前 20 秒等示例写成业务默认值，也不预设超时后直接截断台词、统一加速或循环画面。

### 第一版预览范围

- 先提供简单的成品预览。
- 用户可以调整 BGM 音量、开关字幕。
- 暂不做逐片段替换、修改某句台词、时间线精修等预览内编辑。
- 用户不满意时可以返回前面的制作阶段，保留配置，在实例允许的范围内调整黑色内容和制作设置，再覆盖生成；不要求重新上传已保留的素材或清空配置。
- 返回前面不开放红蓝公共资源编辑或模板结构编辑；需要修改公共资源或模板时，回到对应管理界面，新框架用于新的实例。
- 保留配置不等于无条件复用旧结果。发生内容或资源可用性变化时，需要重新核对相关步骤；不默认自动提交付费重生成。
- 预览内的调整权限在正式完成后关闭，以“预览、正式完成与参数快照”一节为准。

## 当前正常使用流程

1. 在资源库中导入已经准备好的主播片段，准备蓝色文案与配音，整理商品信息和产品素材。
2. 使用完全可用的资源制作并保存文本模板；到此停止也是一次有效操作。
3. 选择模板和本次商品输入创建实例，保存实际采用的框架及资源引用，检查是否有失效依赖。
4. AI 根据上下文补全黑色文本，用户检查、修改和确认。模板完成其参考作用，实例不依赖模板后续存续。
5. 生成黑色配音；需要时继续匹配产品画面，与红色原视频、蓝色配音共同编排合成。
6. 预览成品，调整 BGM 和字幕，必要时返回前面的允许阶段重做；同一实例覆盖当前结果。
7. 正式完成，保存独立成片和只读参数快照，再清理不需要继续保留的黑色独立音频。

正式完成前可以保存进度后离开，后续继续，不要求每次都从资源准备走到成片。

## 后续需要回答的问题

- 商品删除的具体范围、价格卖点和所属素材如何处理、与未完成实例有什么关系；当前整体未定。
- 数据根目录的具体路径、数据库与媒体目录布局；资源独立保存媒体文件、第一版不做备份和跨资源文件去重的规则已确定。
- 资源准备阶段如何录入或获得准确台词，以及“完全可用”的具体校验方式；不扩展为从长直播自动挖掘片段。
- 黑色位置是否附带补全意图、风格或长度约束，以及具体 AI 补全和配音调用方案。
- 灰色失效引用被移除后，已有黑色文本和配音需要用户复核还是重新生成；不因此自动提交付费请求。
- 返回前面的制作阶段后，哪些结果可复用、哪些已失效，产品画面如何选择、素材不足时如何处理，以及费用如何提示。
- 任务释放文件占用后的清理实现，以及未完成实例工作文件的具体保留规则；资源删除后需要清理对应媒体文件的原则已确定。
- 最终时长规则、允许误差和素材不足时的处理，由业务方确认。

## 与早期调研建议的关系

- MoneyPrinterTurbo 继续作为可复用执行层候选，不代表原样满足混合原声与 AI 配音的流程。
- 早期“先整段文案再插入”和“先选主播再衔接文案”的比较保留为演进背景；当前先以红蓝内容及黑色补全位置组成的模板为业务基线，不再要求每次从主播素材池自动重选。
- “商品归属全部素材”不适用于通用主播素材池，商品素材和主播素材要区分。
- 逐段修改预览的建议暂不纳入第一版范围；第一版采用简单预览及保留配置返回允许阶段重跑。
- 模板制作与使用是独立能力，用户可以只制作模板，或只完成文案和配音，不必生成视频。
- 蓝色和黑色默认分开准备配音，以满足蓝色复用；黑色先经用户确认文本。
- 实例不与模板保持持续绑定；来源模板仅作记录。公共资源实际内容修改另存新 ID，不向旧引用传播。
- 第一版不保留同一实例的多次生成历史，不做备份功能，不提供删除主播的操作。
- “引用中就禁止删除”的旧建议不采用；当前采用资源标记已删除、引用灰显、阻止继续、允许移除失效引用的规则。
- 跨资源共享媒体文件不是当前方案。每个资源独立保存媒体，删除资源时清理其托管文件并保留已删除记录；商品整体删除继续保持未确定。
- 以本文件已确认的业务规则为设计基线，不先搭完整编辑器或把技术字段、数据库模型当作已确认需求。
