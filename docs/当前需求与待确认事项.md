# 电商视频混剪当前需求与待确认事项

更新日期：2026 年 10 月 20 日。

本文件作为现阶段需求基线，记录已确认的业务约束，优先于早期调研报告中的示例和实现建议。后续有调整时再修改本文件，不把旧建议继续当成待选方案。当前处于需求与方案讨论阶段，不代表客户端已实现这些功能。

## 当前目标

用户通过文本制作和使用模板，将已有主播片段、必要 AI 口播和 AI 补全文案组织起来；需要时再配合用户上传的产品素材生成电商视频。

模板制作和使用独立于视频工作流。一次操作可以只制作并保存模板，也可以停在文案或配音准备阶段，不强制继续生成视频。

## 已确认的约束

### 文本驱动的三色模板

| 类型 | 内容含义 | 交互与资源关系 |
| --- | --- | --- |
| 红色 | 提前保存、完全可用的主播原话和原视频片段 | 界面展示文本，点击句子查看已绑定的视频资源 |
| 蓝色 | 提前在资源库准备好的必要 AI 口播及配音 | 界面通过文本操作，点击句子查看对应音频；可跨模板、跨实例复用 |
| 黑色 | 模板中待补全的文案位置 | AI 根据整体上下文生成文本，用户确认后再配音 |

- 用户主要在文本界面组装、排序和操作模板，不要求在时间线或视频缩略图上完成模板制作。
- 红色内容对应主播真实原话，不由 AI 改写；蓝色内容保留其必要口播属性；黑色是允许 AI 补全的部分。
- 黑色位置首先是内容待补位置，不预设为已经确定秒数的视频空白。
- AI 补全需要考虑整个模板的红色、蓝色内容及其他黑色位置，避免逐个孤立补写造成重复和断层。
- 素材准备、文案生成、配音和视频合成是可分开的阶段，不把模型返回文本或普通阶段完成当成自动执行全链路的指令；黑色文案经用户确认保存后的配音生成，按后文明确规则执行。

### 两类片段及其音画关系

- 主播片段使用原视频对应的画面和原声，作为完整音画单元处理，不默认替换其声音。
- AI 配音片段使用 AI 文案与配音，画面使用用户上传的产品素材。
- 产品素材用于成片时原声静音，不与 AI 配音叠加；红色主播片段仍使用其原视频、原声。
- 最终声音由主播原声与 AI 配音穿插组成，不是一条 AI 旁白覆盖所有画面。
- BGM 是独立音轨，不参与主播与 AI 配音的内容顺序决定。

### 主播素材跨商品复用

- 第一版只接收用户已经准备好的主播片段，不要求从长直播中自动筛选、切分或按句导出。
- 主播片段通常是通用话术，不出现具体商品，不应为每个商品重复保存一份。
- 以主播身份组织可复用素材池；某次任务引用其中的具体源片段。
- 产品素材与商品关联，和主播素材分开管理。产品维度可以限制某次任务允许使用的素材，不意味着主播素材归商品所有。
- 同一主播的多个片段需要考虑语义完整性、前后衔接、重复，以及画面和声音连续性。通用不等于任意位置都可使用。

### 资源入库识别与描述

- 当前采用云端多模态模型调用方案，暂时不集成本地语音识别或画面理解模型，不在客户端安装包内携带或首次使用时下载这类模型权重。
- 主播片段由客户端自动提取音轨，只把音频交给支持音频输入的模型识别台词，不为获取台词上传视频画面；用户不需要手动提取音频。
- 转写目标是忠实保留原声台词，不是总结或改写；品牌、价格和数字的准确性需要用真实素材验证，不能只凭模型支持音频就认定结果准确。
- 商品原素材做画面理解，确定可独立使用的内容范围及对应描述，再实际切分并按独立片段入库；分析采用完整视频还是抽帧、如何采样，留待具体实现讨论。
- 主播台词转写与商品画面描述可以使用同一支持音频、视觉输入的多模态模型或接口，但输入按任务分别处理；具体模型、渠道及请求格式尚未选定，不把此前用于估算价格的模型视为已选型。
- 台词和描述保存为资源信息，供标题展示和后续使用。资源内容没有改变时复用已经取得的结果，不在每次创建模板或实例时重复识别；仅修改展示标题不自动重新调用识别。
- 本机存储不等于 AI 全部离线运行：这套方案需要联网，识别请求会将所需音频或画面发送到采用的模型服务。

### 商品素材切分后独立入库

- 商品素材采用实际切分后入库的方式：每个可独立使用的片段成为一条正式资源，有自己的资源 ID、托管视频文件和描述标题。
- 模型提出有意义的展示内容或完整动作范围，并为每段提供描述；本地程序实际切出视频、校验文件并记录实际时长，只有可正常使用的片段才进入后续选择面板。
- 切分以完整展示或动作作为单位，不按每秒或最终配音所需的固定秒数机械切分；例如一次完整按压及松开的过程，不拆成多个无法独立表达的细碎资源。
- 对已经是单一完整内容的短片，不要求为了切分而再次切碎，可以直接作为独立资源入库。
- 片段描述作为名称保存；素材 ID、所属商品和实际时长等信息仍分别记录，不能只保留标题而丢失媒体身份和基本信息。具体描述字段仍待讨论。
- 用户最初选择的原始视频文件保持不动，不覆盖、不修改、不删除。客户端中的长视频导入副本仅作为入库工作文件，不作为所有正式片段必须依赖的长期源文件。
- 分段结果切出、校验和入库成功后，可以清理客户端临时导入副本；未完成或失败时保留处理所需文件，不能提前清理导致无法继续。
- 可保留来源文件名和切出范围等追溯信息，但正式资源直接引用自身的视频文件，不依赖临时长源继续存在。
- 不长期保存客户端长源的代价是：之后扩大切分边界或找回未入库的内容，通常需要重新导入原始视频；修改标题不能恢复未保存的画面。
- 这项切分规则只针对商品素材，不把主播原片段的导入扩展成从长直播自动挖掘片段。
- 后续文案与画面匹配以这些独立资源为基本单位，不再从长源视频中查找动作，也不默认对每条入库片段进行内部语义裁剪；时长适配采用后文的整片段选取、补足和末尾截断规则。

### 业务归属与资源身份

| 对象 | 关联内容 |
| --- | --- |
| 商品 ID | 商品价格、卖点、商品视频片段等产品素材 |
| 主播 ID | 该主播已经准备好的直播视频片段，即红色资源 |
| 通用口播资源 | 蓝色文案与配音，不强制绑定具体商品 ID 或主播 ID |
| 模板 | 文本结构、红蓝资源引用和黑色待填位置，不强制归属于具体商品或主播 |

- 不强制绑定商品或主播，不等于没有资源自身的 ID。资源、模板和实例均需独立身份。
- 界面可以按商品、主播、资源类型组织；界面分类不要求与磁盘目录一一对应。
- 主播视频片段使用主播说的台词作为标题；商品视频片段使用对片段内容的描述作为标题。标题是展示信息，修改它不改变实际视频或原声。

### 公共资源的准备、修改与可用性

- 所有公共资源的导入、创建和修改都在资源库中完成。模板制作和实例界面不提供这些操作入口。
- 蓝色资源只有同时具备文案和与之匹配的有效配音，才能成为正式、完全可用的资源。
- 红色资源也必须具备对应台词和可正常使用的原视频、原声，才能进入后续制作阶段。
- 准备中、配音失败或文件缺失等不完整内容，不作为正式可选资源出现在模板制作、视频制作和实例创建的资源选择面板中。
- 资源库内的准备过程，不意味着用户已获得一条可被后续流程引用的正式资源。准备过程的具体界面和内部状态字段尚未锁定。
- 只修改资源名称，可以保留原 ID。
- 主播片段只修改台词标题，或者商品视频片段只修改描述标题，不创建新资源 ID，也不因改标题重新复制视频。
- 蓝色资源的配音文案不是单纯的展示标题。修改文案或配音中的任意一个，都按新公共资源保存：分配新 ID，提示用户取新名字，旧资源保持不变。文案改变后需重新生成匹配的配音；只更换配音时，文案可以沿用，但不能把旧音频当成新配音。
- 其他实际媒体内容变化，例如用另一段视频替换主播片段或商品片段的原视频，也不能覆盖旧公共资源，应保存为新资源、新 ID。
- 已引用旧资源的模板和未完成实例不自动切换到新资源。需要使用新资源时，在模板制作阶段显式选择。
- 文案和音频不匹配时不能把旧音频当成有效配音；修改后的新资源需重新完成准备，才能被后续流程选择。
- 新选择面板只显示完全可用资源；既有引用后来失效时，保留灰色占位并按下文的删除规则处理，不静默隐藏或替换。

### 哪些操作产生新的业务 ID

以下区分商品、主播、资源、模板和实例各自的业务 ID，不把临时文件名、模型请求号或后台防止旧结果覆盖的标识当成新的公共资源身份。

| 操作 | 新 ID 的归属 |
| --- | --- |
| 新建一条商品记录 | 新商品 ID |
| 新建一条主播记录 | 新主播 ID |
| 导入并保存一条新的主播视频片段 | 新资源 ID；关联已有主播不代表新建主播 |
| 导入并保存一条新的商品视频片段 | 新资源 ID；给已有商品添加素材不代表新建商品 |
| 将商品长素材切分成多个独立片段并入库 | 每个正式片段各有新资源 ID 和独立视频文件；临时长源不作为必须长期保留的公共资源 |
| 创建一条新的、文案与配音齐全的蓝色资源 | 新资源 ID；准备阶段何时分配内部标识属于实现细节 |
| 修改正式蓝色资源的文案或配音，并保存新内容 | 新资源 ID；保留旧资源及其已有引用 |
| 更换主播或商品片段的实际视频内容，并保存新内容 | 新资源 ID；不是对旧视频原地覆盖 |
| 新建一个模板 | 新模板 ID |
| 新建一个使用实例 | 新实例 ID |

以下情况不因为操作本身创建新的公共资源 ID：

- 修改主播片段的台词标题、商品片段的描述标题，或资源仅用于管理的名称，不改变实际媒体内容。
- 将已有资源引用到另一个模板或实例中：使用原资源 ID；新建的模板或实例有自己的 ID，两者不要混淆。
- 编辑和保存现有模板：更新该模板的框架，不因此新建其引用的公共资源；只有显式新建另一模板才产生另一模板 ID。
- 在同一未完成实例中重写黑色内容、重新生成黑色配音、调整预览或覆盖成片：沿用当前实例，不把黑色工作文件自动变成公共资源。
- 删除资源：保留原资源 ID 并标记已删除；在模板管理中移除灰色失效引用不创建新资源。
- 未完成实例因红蓝资源失效而回退到选择模板阶段：沿用当前实例 ID，重新选择有效模板并走后续流程，不自动新建实例或公共资源。

### 红色资源在模板制作阶段确定

- 制作模板时可以通过选择资源、搜索原话等方式确定红色句子；具体辅助搜索和自动选取的实现尚未定案。
- 模板使用时，红色节点已经关联明确的视频片段，不再临时去主播池寻找内容。
- 点击红色句子是查看其对应资源，不是隐式重新选片。
- 同样的文本可能对应不同视频版本，不能仅凭台词文本识别具体资源。
- 自动选取或检索能力主要服务于素材准备和模板制作，不再被设定为每次生成视频的必经步骤。

### 蓝色配音独立生成与复用

- 蓝色部分可能在多个模板或多次使用中复用，应作为可单独操作的文本和音频资源。
- 不默认将相邻蓝色和黑色合成一个不可拆分的配音文件。此前整段合成的效率建议不作为当前方案。
- 蓝色文字和配音先在资源库准备齐全，再作为一个正式资源供模板引用。
- 模板和实例点击蓝色文本时播放已经绑定的配音，不在这些界面临时生成或修改蓝色资源。
- 不引入同一资源 ID 下多份可切换内容的隐式更新机制；实际内容变更按新资源、新 ID 处理。

### 音色选择与参考音频

- 提供多种可选音色，并允许用户上传参考音频创建新音色。
- 后续优先借鉴现有视频智能体客户端的音色管理、参考音频上传和试听等相关实现；这不代表当前新工作流已经集成或可直接复用所有接口。
- 蓝色公共口播在资源库制作时选择音色；已正式保存的蓝色口播改变音色或配音后，仍按新资源、新 ID 保存，不能在实例中悄悄替换原有配音。
- 黑色配音在实例中选择音色；仅重新配音不改动其文案。
- 红色片段保持主播原声，不因实例选择 AI 音色而统一换声。
- 具体音色服务、参考音频要求和接口兼容方式待实施时核对。

### 黑色文案与音频分别确认

- 使用模板时，AI 根据商品信息、红色主播原话、蓝色必要口播和模板规则补全黑色文本。
- 第一版不为每个黑色位置提供用途、风格或长度要求的配置入口，由 AI 理解完整模板及前后文，整体安排各处补全文案，不要求用户逐个解释空白位置的作用。
- 文案确认和音频确认是两个独立节点，分别记录状态；确认文字不等于确认声音，配音生成成功也不等于用户已经确认音频。
- 用户检查、修改并确认文本之后，进入黑色配音生成；用户试听并确认音频后，才进入后续画面匹配与视频合成。
- 由开发侧预先准备统一补全提示词，按效果需要提供范例，引导 AI 理解红蓝黑结构、自然衔接及各黑色位置的填写方式；提示词和范例的具体内容后续设计验证，不新增用户逐位置配置或编辑提示词的前置要求。
- AI 只补全黑色位置，不改写已绑定的红色原话、蓝色文案或其顺序；生成结果仍按既定流程由用户检查、修改和确认，再进入配音。
- 价格、活动、商品属性等内容应依据确认的信息；已有主播片段中的活动话术也需要与本次条件相符。
- 范例用于示范结构、语气和衔接方式，不能把范例中的商品、价格、活动或效果主张当成当前商品事实直接照搬；缺少依据的信息不由 AI 自行编造。
- 黑色生成内容属于本次使用的结果，不默认覆盖原模板的待补位置。
- 在最终视频生成前的文案、配音准备阶段，黑色文字可以反复修改和确认，也可以重新生成配音；不因此获得修改红蓝公共资源的权限。
- 修改黑色文案并确认保存后，对应旧配音及音频确认自动失效，并重新生成与新文案匹配的配音。触发点是用户确认保存，不是用户每次输入文字。
- 新生成的配音仍需试听并确认；如果生成失败，不能把已经失效的旧配音当成新文案的有效音频继续制作。
- 如果不改文案、只重新配音，保留文案及其确认状态，只更新配音并重新进行音频确认。
- 黑色独立配音属于实例工作文件，不作为公共资源自动入库。
- 未完成和预览阶段保留继续制作需要的黑色配音。正式完成且最终视频已可靠保存后，可以清理这些独立音频，最终快照仍保留黑色台词和使用的生成参数。
- 不为黑色补全预设固定秒数；最终长度仍由用户确认后的实际配音及主播原声决定，不以新增逐位置长度字段替代整体理解。

### 逐句台词时间与字幕数据

- 文案和配音确认后，在画面匹配与合成之前，产出或读取可复用的逐句台词时间，并保存到本机结构化数据中，供字幕使用；不等成片后再重新识别整条视频来生成字幕。
- 红色使用主播真实原声对应的台词，蓝色使用已绑定的配音，黑色使用本次确认的有效配音。时间信息必须与实际文案和音频匹配，不按字数均分，也不让文字模型凭感觉估算。
- 片内时间指每句话在所属音频中的起止位置。保留它是为了逐句显示字幕及复用对齐结果，不代表把完整口播拆成多个资源或多个音频文件；只有一句的口播不强制再拆细。
- 红蓝公共资源可以保存、复用与其媒体一致的对齐结果；黑色时间信息属于当前实例节点，不自动成为公共资源。同样的文案重新配音后，不能直接沿用旧音频的时间。
- 实例记录各红蓝黑节点在全片中的放置位置；全片台词时间由节点开始位置与片内时间计算，不要求平时重复维护两套独立时间。实际采用的全片台词及时间在正式完成时保留为只读快照。
- 音频中的停顿仍占用全片时间。停顿时可以没有字幕，但对应画面仍需覆盖；字幕换句不强制触发切镜头。
- 黑色文案修改并确认保存后，随旧配音失效，其时间信息也不再有效；新配音确认后重新取得对应时间。仅重新配音时文字可以保留，但时间需重新核对，并重算受影响的后续全片位置。
- 时间数据与资源或实例节点、对应文字及实际音频建立关联；具体表结构、字段、时间单位和精度在实现时细化，不在本轮锁定。
- 实际字幕文件（例如 SRT 或 ASS）由当前实例的台词文字及全片时间生成，是制作输出，不替代数据库中的原始对齐数据。JSON 可按调试或处理程序需要导出，不额外维护一套必须同步的长期主数据。
- 具体对齐服务及配音接口是否能直接返回可用时间信息，留待选型验证；当前只确定逐句时间需要产出并保存，不因此指定额外模型或本地模型权重。

### 文案与产品画面的匹配是独立节点

- 将文案与视频片段的匹配作为独立工作节点，不和文案生成、配音生成捆绑为一次不可分开的执行。
- 该节点使用已经确认的完整文案、配音、时间信息，以及当前商品的可用片段和描述，安排 AI 配音部分对应的产品画面。商品片段标题描述的是画面内容，不是要朗读的配音文案，也不直接作为字幕。
- 第一版采用“文案与商品素材文字目录交给云端模型选择素材 ID，本地程序校验并拼接”的路径。请求使用已经入库的描述标题、素材 ID 和实际时长等信息，不在每次匹配时重新上传该商品的全部视频。
- 模型负责语义判断和展示顺序，给出与当前文案直接相关的匹配候选，以及适合承接当前文案的同商品通用补充候选。两组是本次选择结果，不是素材必须具有的永久分类。
- 候选排列应兼顾完整文案的内容顺序，而不是只按相关程度从高到低排列；第一版不要求画面在每句话说出时精确切换。
- 本地程序限定商品和资源可用性，核对返回的 ID、文件及真实时长，并在模型给出的合适候选中累加、补足和安排重复，不必每补一段就重新调用模型。
- 在文字目录可容纳的情况下直接提交候选描述；第一版不引入本地匹配模型或向量数据库。素材规模变大后是否增加语义向量检索和候选排序，留待后续，不作为当前前置条件。
- 红色主播原视频已由模板绑定，继续作为完整音画单元使用，不在此节点重新从主播素材池选片，也不允许商品画面覆盖其位置。
- 基本选片单位是已经语义切分、独立入库的资源，不要求额外标注片内动作时间，也不把素材硬分成“可裁剪展示”和“必须完整播放动作”两类。

### 整片段选取、补足与末尾截断

- 以连续 AI 配音对应的商品画面区间为时长预算；相邻蓝黑配音可以共享商品画面的拼接安排，但声音仍按各自完整单元顺序播放，区间不能跨越红色主播片段。
- 优先按模型给出的匹配候选顺序选取整条独立资源，按本地读取的真实时长累加。累计时长大于或等于对应音频长度即停止；恰好相等时不额外添加片段。
- 匹配候选不足时，从同商品、当前可用且适合承接本段文案的未用通用补充候选中继续选取。不是把商品名下所有剩余素材无条件用完；明显不相关或与台词冲突的画面不用于凑时长。
- 所有本次适合使用的候选用过一遍仍不足时，允许重复使用已选的合适片段，直到覆盖音频。程序尽量优先使用次数较少、距离上次出现较久的片段，避免相邻重复；仅一条可用素材时允许连续重复，具体排序细节留待实现。
- 实际出现重复时，在预览或结果中提示“素材较少，部分商品画面已重复使用”等通俗说明；不因重复中断任务，也不每重复一次就弹窗。完全没有可用素材时提示补充素材，不能进入无效的重复循环。
- 选片阶段不为每条资源寻找内部语义裁剪位置。累计超出音频长度时，只截去拼接画面末尾的超出部分，即最后一条资源从开头保留剩余需要的时长；前面的选中片段完整使用。
- 实现时可以先计算最后一段需要保留的长度，一次生成最终长度的视频，不要求先导出过长视频再二次处理。所有截尾只影响当前实例的输出，不修改资源库原文件，也不新增公共资源。
- 第一版不自动变速、倒放、定格，不为画面凑时长改写台词、截短配音或挪动红色主播片段。
- 质量预期是优先保证段落层面的画面相关性及顺序，不保证逐句台词与镜头切换严格对齐；通用补充不是直接展示每项台词所指动作，最后一个片段也可能在动作完成前被截断。此为当前简化策略接受的边界，不再引入强制保全动作或跨句借时长的额外流程。
- 字幕继续按实际台词时间显示，不随画面切换或重复重新计时。比如需覆盖 8 秒，先选 3 秒和 2 秒匹配片段，再补一条 4 秒通用片段，最终只保留该通用片段开头 3 秒，得到 8 秒商品画面。

### 资源 模板 使用实例三层关系

- 资源层保存可复用的主播片段、蓝色文本与配音、产品素材等内容。
- 模板层保存文本结构、节点顺序、红蓝资源引用，以及黑色补全位置和相关规则。
- 使用实例保存某次制作的输入、节点内容、实际资源引用、确认结果、工作进度及可选的视频结果。
- 模板提供参考框架，不是贯穿实例全生命周期的运行依赖。在实例初始化、为 AI 生成黑色部分提供上下文后，实例按自身已经保存的内容继续制作。
- 实例可以记录来源模板的 ID 和名称，用于说明“使用过哪个模板”；这些信息本身不建立持续的依赖或同步关系。
- 模板后续修改或删除，不改变已创建实例的内容，也不妨碍实例按已保存内容继续运行。
- 实例仍可直接依赖红蓝资源和产品素材。模板不再参与，不代表这些实际媒体依赖也随之消失。
- 模板制作只选择和组装公共资源，不修改资源内容；实例按自己的既定框架处理黑色部分和后续制作，不编辑红蓝资源或任意调整模板结构。
- 未完成实例不提供移除失效红蓝节点后继续制作的例外；实际引用的红蓝资源失效时，按后文规则回退到选择模板阶段。仅来源模板自身修改或删除不触发这一回退。

### 实例保存、覆盖与恢复

- 实例是可以保存和续做的一次工作，不仅指完成后的视频记录。用户可以暂停实例 A，处理实例 B，再返回 A 继续。
- 保存当前商品输入、采用的节点与规则、资源引用、黑色文本、文案确认与音频确认各自的状态、已完成配音及有效逐句时间、节点放置位置、当前选片与重复使用记录、制作配置、工作文件和当前阶段。
- 同一实例重新生成时覆盖当前结果，不保留多次生成历史或多套运行版本；用户显式新建实例时才另存一份独立工作。
- 暂停、失败或关闭客户端后，不应因清理工作文件而丢失继续制作的条件。保存工作进度不等于保证外部付费请求可以字面意义上的暂停和续传。
- 覆盖采用先完成有效的新结果、再替换当前结果的方式，避免失败后只剩损坏或缺失的输出。
- 旧请求晚返回时，不能覆盖已经被用户修改或重新生成的较新内容。这是防止结果错配，不是保留多次历史。
- 实例里的商品输入和生成内容需要保持对应，不在恢复时从公共库悄悄混入新价格、新台词或新音频。

### 红蓝资源失效后的实例回退

- 此规则适用于未完成实例，包括已经生成预览但尚未正式完成的实例：实际引用的红色主播资源或蓝色口播资源被删除、媒体缺失等导致不可用时，不能移除该节点后继续原流程，也不在实例中开放修改模板框架的入口。
- 发现此类失效后，停止推进旧流程，向用户说明所用资源已不可用，将当前实例进度回退到选择模板阶段；沿用同一个实例，不要求另建实例。
- 保留当前商品输入和仍可使用的通用制作配置。旧框架下的黑色文案、配音及其确认状态、台词时间轴、选片安排和预览结果不再计作当前流程的有效进度；不能只换掉失效资源后沿用旧结果继续。
- 用户只能重新选择资源齐备的有效模板。原模板若仍有失效引用，需要在模板管理中单独修复，或者改选其他有效模板；回退本身不修改原模板，也不自动替换其中资源。
- 重选并确认模板后，从黑色文案补全、文本确认、配音及音频确认继续重新走后续流程。回退本身不自动提交新的付费请求；用户按正常流程重新发起生成时，可能产生新的费用。
- 旧流程中尚未返回的请求不得在回退后恢复旧进度或覆盖重新选择模板后的内容。回退不等于保证外部已提交任务能撤销或退费；相关文件仍按占用释放和安全替换规则处理，不在此要求立即物理删除所有旧工作文件。
- 已正式完成的实例不回退，独立成片和只读快照不受公共资源后续删除影响。本次规则针对红蓝框架资源失效，不据此推定商品删除或商品画面素材失效的全部处理方式。

### 预览、正式完成与参数快照

- 生成了可预览视频，不等于实例已经正式完成。
- 预览阶段允许调整 BGM、开关字幕；这些修改仍属于未完成的制作过程。
- 正式完成且最终视频可靠保存后，实例进入“已完成”状态，不再提供参数修改或重新生成入口；需要另做时新建实例。
- 已完成实例以独立成片和只读参数说明面板呈现。快照记录当时实际使用的商品信息、模板来源、红蓝资源信息、黑色台词、声音设置、BGM、字幕等相关配置，以及实际采用的台词与全片时间、画面安排和重复使用情况；这些文字及时间记录不因后续清理临时黑色音频或删除公共资源而消失。
- 商品之后涨价、公共资源之后修改、删除或模板之后删除，都不反向修改该快照和成片。
- 只读快照中的来源信息不是必须持续有效的运行引用；不承诺删除源资源后还能播放源片段或基于它直接重做。
- 已完成实例不因历史来源删除而变为不可用，也不在参数面板里提供“移除引用”这类编辑入口。

### 第一版本机存储范围

- 第一版只考虑用户本机存储，不要求登录、跨电脑同步或多人共享。
- 多人共享如有需要另行设计，不作为当前实现的前置条件。
- 程序安装目录与用户数据目录分开。为数据指定一个统一根目录，保存公共媒体、业务记录、模板、实例工作文件、成片和必要缓存；具体路径尚未选定。
- 导入媒体时复制到客户端管理的文件库，原文件保持不动，后续制作不依赖用户桌面或下载目录中的原始位置。
- 每个资源独立保存自己的托管媒体文件，不同资源不共享同一份物理媒体文件；第一版不做跨资源文件去重。
- 模板和实例引用已经入库的同一资源时，不各自重复复制一份长期公共媒体。
- 多个模板或实例引用同一个资源，只是同一资源的多处引用，不是多个资源共享一份媒体文件。
- 主播和商品视频只改标题时，继续使用原资源和原视频；蓝色资源修改文案或配音后，准备新的有效配音并另存资源和独立媒体文件。
- 第一版不做备份、恢复或云同步功能，也不把这些作为当前实现前置条件。
- 结构化数据采用本机 SQLite 的存储方向，不要求另外安装或部署数据库服务；音视频仍作为独立媒体文件存放，不把媒体内容全部塞入数据库。
- SQLite 的具体接入方式、数据表组织、字段、索引、目录布局及缓存实现留到实现时细化；当前不是已完成数据库接入的声明，也不预设每个实例保留多次运行目录。

### 公共资源删除与失效引用

- 删除资源前展示它被哪些模板和未完成实例引用，但不因为存在引用就强制禁止用户删除。
- 确认删除后保留原资源记录，包括原 ID、标题和“已删除”状态，供历史来源和灰色失效条目显示；不把该 ID 分配给新资源，不自动替换成另一资源，也不连带删除引用它的模板或实例。
- 删除资源时一起清理该资源独立拥有的托管媒体文件及对应缓存，不因模板或未完成实例仍有引用而继续保留这些媒体文件。
- 清理范围不包括用户最初导入的原文件、其他资源的文件或独立成片；清理媒体不等于删除已删除记录。
- 新资源选择面板不再显示该资源。已经引用它的模板可保留灰色失效条目，在模板管理中提供移除引用的入口；未完成实例的失效红蓝引用只用于说明原因，不提供删除节点后继续原流程的按钮，而是回退到选择模板阶段。
- 模板管理中的移除只解除当前模板的这一处引用，不再次全局删除资源，也不影响其他使用方；未完成实例按自身实际资源状态执行回退，不自动跟随模板修复。
- 不能用带失效引用的模板启动新的制作；未完成实例的红蓝依赖失效时回退并重新选择有效模板，其他失效媒体也不能被当成可用文件继续执行。
- 模板管理移除失效引用后，要重新检查模板内容是否齐备。原先“实例内移除灰色节点，再决定是否复核旧文案和配音”的例外被整体回退规则替代，不再沿此路径继续。
- 已完成实例按只读快照规则处理，不要求用户为历史来源删除修复成片。
- 若媒体文件正被运行中的任务读取，先将资源标记为“已删除”，阻止后续使用，待任务结束或停止、释放文件占用后再清理；没有运行占用时随删除操作直接清理。占用解除前的暂缓清理不代表保留可恢复资源，也不影响其他界面显示已删除状态。

### 商品、主播与模板的删除边界

| 操作 | 当前规则 |
| --- | --- |
| 删除商品 | 未确定；是否提供该操作、删除范围及与未完成实例的关系，后续单独确定 |
| 删除主播 | 第一版暂不提供该操作，避免牵连红色资源与模板引用 |
| 删除模板 | 仅释放该模板对资源的引用，不删除公共资源，也不删除或修改已创建实例 |

- 商品删除整体先标记为未确定，不在本轮锁定删除商品时是否连带处理其素材、是否阻断未完成实例或采用什么具体交互。
- 已完成成片和参数快照作为独立单元、不随公共信息变化的原则保留，但不据此推定商品删除的具体规则。
- 删除模板只减少该模板实际持有的引用，不代替实例释放其独立的资源引用；来源模板信息不构成保留模板的理由。

### 最终视频时长跟随主音频

- 实例准备完整文案及配音后，以最终编排好的主音轨实际时长作为成片时长依据，不由开发人员预设固定时长或目标时长范围。
- 主音频包括按红蓝黑顺序使用的主播原片段原声、蓝色公共配音和黑色实例配音，不只是 AI 配音部分；红色画面与其原声保持同步。
- BGM 是独立音轨，跟随主音频和成片长度，不反过来决定视频总时长。
- 产品画面按“匹配片段优先、通用补充、必要时重复、末尾截断”的规则覆盖对应配音长度，不因此擅自截断台词或统一加速配音。
- 画幅、分辨率和字幕样式尚未形成明确规格，不因时长规则已确定就默认沿用旧客户端的固定参数。

### 第一版预览范围

- 先提供简单的成品预览。
- 用户可以调整 BGM 音量、开关字幕。
- 暂不做逐片段替换、修改某句台词、时间线精修等预览内编辑。
- 用户不满意时可以返回前面的制作阶段，保留配置，在实例允许的范围内调整黑色内容和制作设置，再覆盖生成；不要求重新上传已保留的素材或清空配置。
- 普通返回不开放红蓝公共资源编辑或模板结构编辑；主动修改公共资源或模板时，回到对应管理界面，新框架用于新的实例。实际红蓝资源失效触发的异常回退另按前文处理，允许当前实例回到选择模板阶段重新开始，但仍不提供实例内修改模板的入口。
- 保留配置不等于无条件复用旧结果。普通返回、尚未确认的编辑或资源可用性变化不自动提交付费重生成；黑色文案修改并确认保存后的配音生成，按文案与音频分别确认的规则处理。
- 预览内的调整权限在正式完成后关闭，以“预览、正式完成与参数快照”一节为准。

## 当前正常使用流程

1. 在资源库中导入已经准备好的主播片段，由客户端提取音轨并调用模型识别台词；商品原素材经模型分段描述、本地实际切分和校验后，每段独立入库。准备蓝色文案与配音，并整理商品信息，用户原始文件始终不动。
2. 使用完全可用的资源制作并保存文本模板；到此停止也是一次有效操作。
3. 选择资源齐备的模板和本次商品输入创建实例，模板在使用阶段只读；保存实际采用的框架及资源引用，检查是否有失效依赖。
4. AI 根据上下文补全黑色文本，用户检查、修改和确认。模板完成其参考作用，实例不依赖模板后续存续。
5. 按选定音色生成黑色配音；修改文案并确认保存后，使旧配音失效并重新生成。仅重新配音时不改动文案。
6. 试听并确认音频，与文案确认分开记录，得到本次使用的完整文案和有效配音。
7. 在画面匹配之前读取或补齐有效的逐句台词时间，记录各音画节点的位置并计算全片时间，作为字幕的依据。
8. 进入独立的文案与产品画面匹配节点；模型安排匹配及通用候选，本地按连续 AI 配音区间累加整片段，必要时重复，达到时长后仅截末尾。产品素材原声静音，红色仍保留原视频和原声。
9. 从台词及全片时间生成字幕数据，合成并预览成品，实际重复时作出提示；调整 BGM 和字幕，必要时返回前面的允许阶段重做，同一实例覆盖当前结果。
10. 正式完成，保存独立成片、实际台词时间和只读参数快照，再清理不需要继续保留的黑色独立音频。

正式完成前可以保存进度后离开，后续继续，不要求每次都从资源准备走到成片。

异常分支：未完成实例实际引用的红蓝资源失效时，按回退规则返回第 3 步，重新选择有效模板并走后续流程，不移除失效节点后沿用原进度继续。

## 后续需要回答的问题

- 商品删除的具体范围、价格卖点和所属素材如何处理、与未完成实例有什么关系；当前整体未定。
- 数据根目录的具体路径、SQLite 接入和数据表组织、数据库与媒体目录布局；本机 SQLite 的存储方向、资源独立保存媒体文件、第一版不做备份和跨资源文件去重的规则已确定，表结构留到实现时细化。
- 云端台词识别与商品画面描述采用哪个模型和渠道、转写结果如何校对，以及“完全可用”的具体校验方式；主播只传音频、商品实际切分后独立入库、暂不集成本地模型的方案已确定。
- 商品分段边界如何校验和修正、描述准确性如何复核；每段独立资源、描述作为标题、原始文件不动、入库成功后可清理临时长源的规则已确定。不要求为后续选片增加内部动作时间标注或可剪／不可剪分类。
- 逐句音频对齐服务如何选型和校验、配音接口能否提供可复用的时间信息，以及字幕是否需要进一步细分长句；逐句时间保留用于字幕、音频相对时间与节点位置计算全片时间的方向已确定。
- 黑色自动补全的统一提示词及必要范例如何编写和验证、具体 AI 补全服务及配音服务、参考音频要求等仍待设计选型；不提供逐位置用途、风格或长度配置、由 AI 理解完整模板进行补全的方向已确定。
- 商品画面素材失效时，是否只重选画面及如何复用其余结果，留待具体处置设计；不把红蓝资源失效的回退范围自动扩大到所有商品素材。红蓝资源失效时，同一实例回退到选择模板并重新走流程的规则已确定。
- 匹配模型的输出格式、候选及重复排序的具体细节，以及简化选片策略的实际效果验证；整片段优先匹配、通用补充、必要时重复并提示、末尾截断的主规则已确定，不再把这套时长适配策略列为后置待定项。
- 返回前面的制作阶段后，除已确定的文案改动导致配音失效与重生成外，其他结果的复用、失效及费用提示规则。
- 任务释放文件占用后的清理实现，以及未完成实例工作文件的具体保留规则；资源删除后需要清理对应媒体文件的原则已确定。
- 成片画幅、分辨率和字幕样式等输出规格；最终时长跟随实际主音频，不再作为未定的固定时长选项。

## 与早期调研建议的关系

- MoneyPrinterTurbo 继续作为可复用执行层候选，不代表原样满足混合原声与 AI 配音的流程。
- 早期“先整段文案再插入”和“先选主播再衔接文案”的比较保留为演进背景；当前先以红蓝内容及黑色补全位置组成的模板为业务基线，不再要求每次从主播素材池自动重选。
- “商品归属全部素材”不适用于通用主播素材池，商品素材和主播素材要区分。
- 逐段修改预览的建议暂不纳入第一版范围；第一版采用简单预览及保留配置返回允许阶段重跑。
- 模板制作与使用是独立能力，用户可以只制作模板，或只完成文案和配音，不必生成视频。
- 蓝色和黑色默认分开准备配音，以满足蓝色复用；黑色先经用户确认文本。
- 黑色文案由 AI 结合商品信息和完整模板自动补全，不要求用户为每个空白配置用途；开发侧统一提示词及按需提供的范例负责指导填写，不因此允许改写红蓝内容或照搬范例中的商品事实。
- 当前不集成本地识别模型：主播片段只传音频转写台词，商品片段做画面描述，资源内容未变时复用结果。
- 商品素材在入库时实际切成独立资源，不长期依赖一份长视频及时间段描述；原始文件保持不动，客户端临时长源仅在切分、校验和入库成功后才可清理。
- 商品画面采用整片段选取、通用补充、必要时重复并提示、只截末尾的简化时长策略；不默认进行资源内部语义裁剪、硬性动作分类、变速或逐句精准切镜。
- 产品素材在成片中静音；黑色文案与音频分别确认，确认保存修改文案后配音自动失效并重生成，成片时长跟随实际主音频。
- 逐句时间保留用于字幕，不拆分口播资源；本机 SQLite 保存结构化数据的方向已确定，具体表组织及接入在实现时设计。
- 实例不与模板保持持续绑定；来源模板仅作记录。公共资源实际内容修改另存新 ID，不向旧引用传播。
- 第一版不保留同一实例的多次生成历史，不做备份功能，不提供删除主播的操作。
- “引用中就禁止删除”的旧建议不采用。模板管理中可以移除失效引用；未完成实例不保留“移除失效红蓝节点后继续”的例外，而是在红蓝资源失效时回退到选择模板、重新走后续流程，已完成实例不受影响。
- 跨资源共享媒体文件不是当前方案。每个资源独立保存媒体，删除资源时清理其托管文件并保留已删除记录；商品整体删除继续保持未确定。
- 以本文件已确认的业务规则为设计基线，不先搭完整编辑器或把技术字段、数据库模型当作已确认需求。
